# Changelog

## 1.0.0 — 2026-10-16

First public release as **NoteSpace** (developed until now under the working name _Wiki Studio_; the entries below, 1.1.0–1.12.0, are that development history). Everything listed below is included. Compatibility: settings and commands keep their `wikiStudio.*` ids, and files keep their formats (`wiki.yaml`, `wiki_studio:` board front matter, `.wiki-studio-trash`, `api/` collections), so existing workspaces open unchanged. The extension id is now `notespace.notespace`: uninstall a locally installed `wiki-studio.wiki-studio` before installing NoteSpace.

## Development history (as Wiki Studio)

### 1.12.0 — 2026-10-16

API client, interactive API documentation and wiki management (`docs/api-client.md`). **API Client** tab (also the **API** destination of the workspace, Alt+7): request tabs with unsaved indicators, GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS, params synced with the URL, headers, cookies, bodies (JSON, text, XML, form, multipart with workspace files, binary), auth (API key, Basic, Bearer, OAuth 2.0 client credentials and authorization code with PKCE), timeout and redirects; a response viewer with status, time, size, headers, cookies, pretty JSON/XML, raw text, HTML as source, images, search, copy and download; cancel with Esc, send with Ctrl/Cmd+Enter. Requests run in the extension host with TLS always verified, manual redirects that drop credentials across origins, size limits and readable errors. **Paste a curl command** and every option becomes a field; any request converts to **curl** or **Python requests** (URL, `params`, `headers` and `cookies` dicts, `json=`/`data=`/`files=`, `auth=`, `timeout=`). **Collections** are folders of versioned JSON files under `api/` (create, rename, duplicate, move, reorder, delete to Trash, search, run in order, export/import bundles without secrets); **environments** are files whose secret values live in SecretStorage; `{{variables}}` resolve global < collection < environment < runtime < request. **Tests** in a small safe language (status, time, size, headers, JSONPath, regex, response schema) with `set` for request chaining. **Import OpenAPI as API Collection** with a preview. **``http blocks** in pages are interactive in the reader and Studio (editable URL and body, environment, Send, response below), never send on open, ask once per origin and confirm data-changing methods; `# @collection` links a block to a saved request. **History** without bodies or credentials, with a limit and Clear. **Wiki management** on a wiki in the Pages view: **Remove Wiki from Wiki Studio** (files untouched) and **Restore Removed Wikis**, **Delete Wiki Files…** rebuilt (type the wiki name, verified root only, never a workspace folder or a root containing another wiki, unsaved pages handled, Trash first, partial failures reported), **Rename Wiki…**, **Edit Wiki Description…**, **Change Wiki Icon…**, **Change Wiki Color…**, **Set as Default Wiki**, **Open Wiki Settings**. Settings: `wikiStudio.api.folder`, `wikiStudio.api.maxResponseMB`, `wikiStudio.api.historyLimit`. **Boards embedded in pages** (``tasks with `view: board`) are draggable in the reader and Studio, with Alt+←/→ from the keyboard; only the task's line changes. Fix: moving a completed task out of Done on the Status board kept its `done:` date. New `npm run test:api` and `npm run test:embedded-board` browser journeys.

### 1.11.0 — 2026-10-15

Unified workspace, multiple Kanban boards and a planner redesign (`docs/planner.md`, audit and design in `docs/workspace-redesign.md`). One **Wiki Studio** tab with **Home, Wiki, Tasks, Boards, Calendar and Insights**: the Home (today's tasks with progress, inline completion and quick add, a calendar preview, recently edited pages, favorites, pinned boards, the daily note and a single **Create** menu) is the entry point; **Wiki** opens the wiki's real homepage. **Boards are Markdown files** with their own columns (add, rename inline, recolor, icons, default and completed columns, reorder, delete only after moving cards), stable ids (`board:`, `col:`), cards written to the board's file, tasks from any note added to a board without moving them, and **Move into board file** on request. Cards edit inline (title, completion, priority, due date, labels) with a context menu, drag and drop with drop indicators, keyboard moves and optimistic updates that roll back on failure; subtasks are a card's checklist. **Tasks** has list and table layouts, grouping and saved views; the **Calendar** shows start dates and creates tasks on a day; **Insights** collects wiki health and task statistics. The sidebar's Planner view becomes **Workspace** (destinations and boards). New: **Delete Wiki…** on a wiki in the Pages view (confirmation, system Trash where available). Settings: `wikiStudio.home.openOnStartup`, `wikiStudio.boards.folder`, `wikiStudio.notes.folder`, `wikiStudio.tasks.captureTo`. No migration: the earlier board is the **Status board** and `Inbox.md` keeps receiving quick capture. Fixes: quick edits sent together could compute changes from the same text; a refresh could replace a title being edited or text being typed; the panel stayed empty when it opened before the index was ready.

### 1.10.0 — 2026-10-15

Phase 08: workspace navigation, after a feature-by-feature comparison with Workspace Wiki (`docs/workspace-wiki-comparison.md`; independent implementation, no code copied). The Pages view shows **readable labels** for folders and for pages titled by their file name (`getting-started.md` → Getting Started, with a configurable acronym list), lists a folder's `index.md` or `README.md` first, and orders folders and pages with `wikiStudio.explorer.directorySort`. **`wikiStudio.respectGitignore`** (off by default) leaves out pages that Git ignores, with nested `.gitignore` files, negations and live updates, per workspace folder. **`wikiStudio.explorer.autoReveal`** controls following the active page, and **`wikiStudio.openPagesIn`** opens pages in Studio, Code or the preview. Titles used by links, search and exports are unchanged.

Phase 07: advanced documentation, visual blocks and live data. **Live data dashboards** (`.wiki-dashboard.json`, documented in `docs/dashboards.md`): read-only Excel (sheets, tables, defined names, ranges, saved formula results), CSV, TSV, JSON and JSONL; typed columns with locale-aware parsing; a safe formula language (no `eval`) for metrics and calculated columns; metric, progress, chart (bar, line, area, pie, donut, scatter, histogram, time series), table, filter and text widgets on a draggable, keyboard-accessible grid; cross-filtering, drill-down to records, CSV/SVG/PNG export; automatic refresh that keeps the last valid data when a file cannot be read; ` ```dashboard ` embeds of a whole dashboard or one widget; exports only with an explicit opt-in. **Block Gallery** in Studio with live previews from the reader's renderer, search, categories and keyboard insertion, and a **block inspector** for chart, task and embed blocks that rewrites only the changed options. **OpenAPI studio**: response models and schemas, authentication and syntax-highlighted curl samples in references; a searchable endpoint catalog and schema view in the playground, which follows description changes; **Generate API Reference Pages** with marked generated sections, conflict handling for hand edits and out-of-date notices; the playground refuses cloud metadata services, asks separately for local-network targets (checked after DNS) and confirms every request that may change data. **Advanced Search** panel and query language (`"phrase"`, `-word`, `tag:`, `path:`, `heading:`, `prop:`, `link:`, `code:`, `type:`, `version:`, `sort:`) with highlighted previews and recent searches. **Quality engine**: missing alt text, skipped heading levels, several titles, required front matter fields and sections per folder (`quality.rules`), outdated pages from Git (`quality.staleDays`), missing homepage, a transparent health score and quick fixes. **Versions from Git**: browse a tag or branch as a read-only snapshot with its own search and comparisons, and compare a page with a tag or branch — nothing is checked out; static exports with archived versions add `latest/` and `versions.json`. **Code references**: links to source files with `#Symbol` or `#L10-L20` are checked against the language's symbols, reported when broken and open the source; _Insert Code Reference_ and _Show Documentation for This File_.

### 1.8.0 — 2026-10-15

Phase 06.5: contextual block colors. Every documentation block has a semantic default color (notes blue, tips green, warnings amber, dangers red, details purple, navigation cards cyan, examples indigo, quotes and layouts gray), applied as a subtle header tint and thin accent border derived from theme tokens. A circular color control in each Studio block header opens an accessible picker with ten presets and **Use default color**; the choice is stored only when it differs, as `{color=<preset>}` on the opening line, and is kept through Studio/Code/Split, undo/redo, reopening, external edits and every export. Also: **Open Kanban Board** command and a `/Kanban board` Studio block (a live task board for the page). Fixes: block header controls (type, title, collapse) stayed disabled when a page finished loading after the header was drawn; header changes were merged into the previous undo step; an empty container parsed differently from the editor's own document; block type labels lacked contrast in light themes.

### 1.7.0 — 2026-10-15

Phase 06: publishing and hardening. **Export PDF** for a page, a section or the whole wiki (cover, contents, print styling) through an installed Chrome, Edge, Chromium or Brave in headless mode, with a print-ready HTML fallback when none is found. **Export EPUB** (EPUB 3 with navigation, metadata, images, MathML and SVG; validated with W3C EPUBCheck). The static site gets a read-only **calendar** snapshot next to the Kanban board (when planner export is enabled), print styles, full-width pages without navigation, keyboard-scrollable boards, and optional **privacy-first analytics** (off by default; path-only beacons or Plausible to an endpoint you configure, honouring Do Not Track and Global Privacy Control). **Customize Site Theme**: six curated presets, accent with automatic 4.5:1 link contrast, typeface, width and color scheme, with live light/dark previews; the reader uses the wiki's typeface and width. Fixes: Mermaid flowcharts written without spaces around arrows (`A-->B`) rendered a single node; the Planner and notebook export pages were squeezed into the navigation column; the calendar grid columns were uneven; `python3 --version` was probed on every Studio context update and in untrusted workspaces; `SECURITY.md` and `architecture.md` now describe the actual network and process behavior.

### 1.6.0 — 2026-10-15

Phase 05: knowledge and quality, documented in `docs/knowledge.md`. **Content Health** report (broken links, unlinked pages, duplicate headings, ambiguous titles, front matter type problems, empty pages, translation coverage and OpenAPI documentation coverage) and matching diagnostics. **Search** is now an incremental index over page sections with accent-insensitive partial matching and results that open at the matching section; optional **Semantic Search** with an embedding model you run locally. **Languages** (`i18n.languages`, translations in `<lang>/` folders with `translated_from` freshness markers) and **archived versions** (`_versions/<id>/`) with switchers in the reader and the static site. **Page History** from Git with diff, compare and restore (read-only Git commands only). **Review comments** stored as portable JSON. **Import Obsidian Vault** into a new wiki with a preview report. Optional **MCP stdio server** and **AI assistance** (VS Code language models or an explicit OpenAI-compatible endpoint) with consent, secret redaction and diff review. The link graph has a local mode. Pasted or dropped images in Studio keep their clipboard name (`image.png`) and appear at once. Embeds inserted from the `/` menu (notebook, canvas, API reference) now pick an existing file, and missing files are reported by their wiki path. Fixes: native dropdown options were unreadable on Windows; the index missed external edits when file watcher events were dropped (it now also compares file times); the Planner counted tasks in translations and archived copies; the link graph SVG and history panel had accessibility issues.

### 1.4.0 — 2026-10-14

Phase 03: daily notes and planning. Tasks are Markdown task-list items with optional plain-text metadata (`due:`, `start:`, `priority:`, `status:`, `repeat:`, `project:`, `@person`, `#tag`, `^id`), documented in `docs/planner.md`. New **Planner** panel with Today, Upcoming, Inbox, Overdue, Done, a Kanban board (drag or Alt+arrows between columns, reorderable cards and columns, swimlanes, quick add), a month/week/day calendar (keyboard navigation, drag to reschedule, daily-note markers, journal streak and activity strip), a sortable table and a task editor — all reading and writing the same page lines through VS Code edits with native undo. Recurring tasks keep completion history and create the next occurrence. Daily notes get a configurable folder and template and Previous/Next/For Date commands. ` ```tasks ` and ` ```collection ` blocks show live task and page views in pages (reader, Studio preview, opt-in export). Exports keep daily notes, the inbox and task embeds private unless `features.plannerExport` is enabled, which adds a read-only `planner.html` snapshot. ### 1.3.0 — 2026-10-14

Phase 02: every supported documentation construct is now editable in Studio. Nested containers (tabs, steppers, timelines, grids, nested callouts) round-trip, and the `/` menu inserts group containers with their children. Math, keycaps, badges, buttons, tooltips, icons, emoji, footnotes, abbreviations, definition lists, reference links, includes, media embeds, HTML and unknown containers are kept as byte-identical **source islands**, rendered with the reader's renderer and edited in place; `==highlight==` is a real mark. New **Import Audio or Video** command with content-type checks. The reader and static export parse pages in one pass, fixing footnotes, reference links and abbreviations that crossed a container; steppers and timelines are ordered lists; navigation cards are fully clickable; in-text links are underlined (WCAG 1.4.1); export styles use the design tokens. Fixes: multi-paragraph callouts were merged into one paragraph when edited in Studio; four-backtick fences containing three-backtick fences were shortened; an edited island stayed selected so the next keystroke replaced it; opening an already open page created a second Studio editor; the block handle exposed focusable buttons inside `aria-hidden`. New `npm run test:rich` browser journey with axe-core accessibility checks.

### 1.2.0 — 2026-10-14

Product-level UX/UI redesign. Studio is now a document-first editor with a page header (wiki, backlinks, sync state, Studio/Code/Split switcher), a compact icon toolbar with contextual table tools, a selection bubble menu, a grouped slash/insert menu, block handles (insert, drag, move, duplicate, delete), inline callout/container headers, code blocks with language picker and copy, live theme-aware Mermaid previews, an inline link popover, hover cards and Ctrl/Cmd+Click navigation. `[[Wiki links]]` are now editable in Studio and round-trip byte-identically. Studio keeps untouched Markdown lines byte-identical, rebases concurrent Split-mode edits and reports overlapping ones instead of guessing. Mode switches replace the tab in place and preserve unsaved edits even on VS Code versions that revert dirty custom editors. Mermaid no longer renders on white canvases: diagrams follow the VS Code theme in Studio and the reader, and adapt to light/dark in exports. New shared design system for Studio, reader, dashboard and export, including high-contrast support. The explorer uses file-icon theme icons, follows the active page and has grouped context menus with inline actions; Outline and Backlinks became one collapsible **Page** view. The dashboard is a separate workflow surface and no longer embeds the index page or opens unprompted. Fixes: undo right after opening could empty the page; Mermaid rendering failed inside the extension host; tests raced the wiki build; the desktop UI journey could not click inside webviews.
