# Architecture

NoteSpace is a TypeScript VS Code extension. Markdown files are canonical; `wiki.yaml` holds project settings; every other format (canvases, notebooks, OpenAPI descriptions, review files) is an open file in the workspace. No database, service or account is required. esbuild produces these bundles:

| Bundle                                                                  | Runs in               | Purpose                                                   |
| ----------------------------------------------------------------------- | --------------------- | --------------------------------------------------------- |
| `dist/extension.js`                                                     | extension host        | everything below except the webview UIs                   |
| `dist/visual.js`                                                        | Studio webview        | Tiptap editor, block UI, islands                          |
| `dist/planner.js`, `dist/canvas.js`, `dist/api.js`, `dist/dashboard.js` | webviews              | Planner, canvas editor, API Playground, dashboard builder |
| `dist/mermaid-worker.js`                                                | Node worker thread    | Mermaid rendering (isolated globals, time-limited)        |
| `dist/mcp-server.js`                                                    | separate Node process | optional MCP stdio server (started by MCP clients only)   |

| Layer                              | Modules                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pure core (`src/core`, no VS Code) | configuration and themes (`config.ts`, `themes.ts`), Markdown parsing and page model, paths, index and section search (`index.ts`, `search.ts`), rendering and rich blocks, includes, design tokens, icons, source-preserving merge and rebase, tasks and collections, charts, notebooks, canvas, OpenAPI, quality and coverage (`quality.ts`, `coverage.ts`), search query language (`query.ts`), languages/versions (`scopes.ts`), diff, review files, Obsidian conversion, front matter edits, redaction, XHTML and ZIP writers for EPUB; data engine (`unzip.ts`, `xlsx.ts`, `dataset.ts`, `formula.ts`, `dashboard.ts`); OpenAPI models, generated pages and request-target checks (`api-schema.ts`, `api-pages.ts`, `net-safety.ts`); Block Gallery catalog and component options (`block-gallery.ts`, `component-props.ts`); code references (`code-refs.ts`) |

**Data flow.** The index is updated per file from watcher events, open-document edits and a periodic size/mtime comparison (watchers can drop events). Each page update re-parses only that page and re-indexes its sections. Planner tasks, diagnostics, health, search and the graph are derived from the index; translations and archived versions are scopes of the same index, kept apart by path prefix (`<lang>/`, `_versions/<id>/`).

**Rendering.** One renderer serves the reader, Studio previews, the static site, PDF and EPUB, with options for each embed type (charts, notebooks, canvases, OpenAPI, task collections). The site adds navigation, search index, switchers and snapshots; PDF prints a combined page through a local headless Chromium; EPUB converts the same bodies to XHTML (parse5) and packages them with a small ZIP writer.

**Boundaries.** Webview messages have known types and validated values; webview HTML uses nonce-only scripts. The host resolves files only inside wiki/project roots and rejects symlinks. Tiptap loads only in the webview (ProseMirror probes `navigator`, which the extension host flags). Features that touch the network or start processes are listed in [SECURITY.md](../SECURITY.md); none run without a user action or explicit setting.

**Data dashboards.** Sources are read by the host (never the webview), parsed into typed columns and cached per file; a watcher marks a source stale and the builder recomputes. Formulas are parsed into a syntax tree and evaluated by `formula.ts`; there is no dynamic code. Webviews receive computed results only.

**API client.** `src/core/http/` is pure: the request model and variable resolution (`model.ts`), curl parsing (`curl.ts`), code generation (`codegen.ts`), the test language (`tests.ts`), collection files and bundles (`collection.ts`), ```http blocks (`http-block.ts`, `render.ts`), OpenAPI import and XML formatting. `api-http.ts` sends with Node's fetch (manual redirects, limits, target checks from `core/net-safety.ts`); `api-store.ts` owns files, environments, SecretStorage, OAuth and history; `api-client.ts` / `api-client-ui.ts` are the panel and its webview; `http-blocks.ts` serves blocks in the reader and Studio. Webviews never receive secret values and never make requests.

The repository is a single npm package. A standalone CLI and a package split remain follow-up work.
