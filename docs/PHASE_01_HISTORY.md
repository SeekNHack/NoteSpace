## Phase 01 changes

- Explorer page activation now opens the visual custom editor; Code opens native Markdown; Split opens visual and Code side by side. Visual Save/Code/Split requests wait for pending versioned edits. Visual selection and scroll positions are stored in webview state where possible (`src/extension.ts`, `src/visual.ts`, `src/visual-ui.ts`). Existing unsafe-syntax fallback remains intact.
- The reader no longer embeds a second page tree. It retains search, breadcrumbs, outline toggle, backlinks and working page navigation, with Focus Mode and responsive controls (`src/webviews.ts`, `media/webview.js`).
- New Page uses one naming prompt, creates a slugged blank page in the active section, and checks collisions; New Page from Template preserves built-in and workspace templates. New Folder uses the active section while preserving the entered display title. Explicit page paths from the missing-link quick fix retain their spelling so the existing link resolves (`src/extension.ts`, `src/core/paths.ts`). VS Code TreeView has no inline text-entry API, so Quick Input handles naming.
- The native TreeView has persisted favorites and recents, active-page decoration, live filtering, drag/drop and context actions. Wiki Home is backed by actual indexed pages, link resolutions, drafts, indexing warnings, favorites and recent history (`src/activity.ts`, `src/views.ts`, `src/webviews.ts`).
- The visual editor has `[[` page suggestions that insert relative Markdown links, link hover summaries, smart URL paste and clipboard image import. The source editor retains native link completion and hover (`src/visual-ui.ts`, `src/visual.ts`, `src/views.ts`).
- Index reads are cached by root and normalized search text. File watcher changes update individual indexed pages; config/root changes still rebuild the index (`src/core/index.ts`, `src/workspace.ts`).
- Follow-up audit fixed Outline/Backlinks on visual pages, rejected drops onto Favorites/Recent groups, preserved naming at the explicitly selected wiki root, serialized persistence writes for rapid navigation, avoided unchanged Home reloads, and restored the visual cursor across document replacement (`src/views.ts`, `src/activity.ts`, `src/extension.ts`, `src/webviews.ts`, `src/visual-ui.ts`).
- Studio body edits now use a tested minimal UTF-16 replacement that leaves frontmatter untouched. Delayed document notifications at or below the acknowledged version no longer reload the editor; newer external versions preserve cursor and scroll where possible. If a source conflict occurs, the visual draft remains visible, can be copied as Markdown through the VS Code clipboard, and Code/Split still open (`src/core/visual-safety.ts`, `src/visual.ts`, `src/visual-ui.ts`).
- Opening an existing Markdown source editor no longer forces its selection to offset zero. An extension-host assertion was added for cursor preservation, but remains unexecuted here because Electron cannot start (`src/views.ts`, `src/test/integration/suite.ts`).
- Visual `[[` suggestions now clear the previous results while a new query is pending and close when the selection leaves the query. The `/` and `[[` keyboard handlers only intercept keystrokes inside the editor, so toolbar buttons retain native keyboard activation. The code-server browser journey now checks keyboard Save while suggestions are visible; that journey is still blocked here (`src/visual-ui.ts`, `scripts/ui-smoke.mjs`).
- Wiki page and section moves now notify the activity store, preserving Favorites, Recent pages and the active-page URI through commands and TreeView drag/drop. URI rewriting is boundary-aware so a move of `project/` does not alter `projects/`. Favorites/Recent filtering now includes tags like the main Explorer tree (`src/workspace.ts`, `src/activity.ts`, `src/core/activity-uris.ts`, `src/views.ts`).
- Wiki Home's unresolved **page link** count now excludes attachment and image paths, matching the separate asset checks in Validate Wiki. Health counts are computed from the real index and have a unit case with an existing page, two missing pages, a PDF path and an image (`src/core/health.ts`, `src/webviews.ts`).
- Studio now rejects ambiguous, nested or unclosed `:::` directives before visual conversion. Only the five documented, paired callout forms are accepted; malformed variants stay in native Markdown Code mode instead of risking a rewrite (`src/core/visual-safety.ts`, `src/test/unit/config.test.ts`).
- Normal page navigation now opens Studio for Markdown the visual schema can handle and opens native Code for unsupported syntax. This covers Initialize/Open Wiki, quick search, daily notes, duplicate/restore, rename and the main Open Page command. Explicit Open Visual Editor still shows its safety notice. Literal `[[...]]` examples in inline/fenced code no longer trigger the fallback; they are ignored by the existing Markdown link parser and inline-code round-trip tests (`src/extension.ts`, `src/core/visual-safety.ts`).
- Empty-space drops in the native Explorer now move each dragged item to the root of its own wiki, including in a multi-root workspace; dropping a folder already at its root is a no-op. The drop handler also checks the source root against the indexed page (`src/views.ts`).
- New Page/New Folder and rename/move destinations now reject case-only collisions at every existing filesystem path component. This prevents `projects/` and `Projects/` from coexisting on Linux and then colliding when the wiki is copied elsewhere (`src/workspace.ts`). The extension-host suite adds a filesystem assertion; it is pending execution here.
- Programmatic Studio document loads now carry Tiptap's `addToHistory: false` transaction metadata, so initial loads and external document refreshes do not become user Undo steps. The browser journey now checks that pressing Undo immediately after a document loads leaves both the visual text and the Markdown file unchanged (`src/visual-ui.ts`, `scripts/ui-smoke.mjs`). The new browser assertion is pending runtime execution.
- Quick page and folder names now reject segments that become empty after slugging, such as an emoji-only title or a `---` path component. They also trim separator hyphens from valid slugs. This prevents accidental hidden `.md` files and has passing core tests (`src/core/paths.ts`, `src/test/unit/core.test.ts`).
- Studio's safety guard now recognizes Markdown reference definitions with zero to three leading spaces. A direct Tiptap schema probe showed that `   [ref]: Guide.md` disappears when converted to visual Markdown; the new test proves such a page stays in native Code mode before conversion (`src/core/visual-safety.ts`, `src/test/unit/visual-markdown.test.ts`).
- Studio's safety guard now ignores callout, reference, HTML and math markers inside fenced or indented code blocks, using Markdown-it code-block token ranges. Real unsupported syntax outside those blocks still opens Code. The actual Studio schema round-trips a callout containing a fenced example byte-for-byte in a new unit case; the extension-host Studio-opening fixture now includes such code and awaits runtime execution (`src/core/visual-safety.ts`, `src/test/unit/config.test.ts`, `src/test/unit/visual-markdown.test.ts`, `src/test/integration/suite.ts`).
- The Markdown index's existing code-span masking is now shared with Studio's safety guard. Inline examples containing HTML comments, tags or `$$` can open in Studio when the actual schema round-trips them; escaped backticks still leave active HTML blocked. The extension-host opening fixture includes an inline HTML example, but cannot run here (`src/core/markdown.ts`, `src/core/visual-safety.ts`, `src/test/unit/config.test.ts`, `src/test/unit/visual-markdown.test.ts`, `src/test/integration/suite.ts`).
- Studio now queues Save independently of Code/Split while document edits or a save are in flight. It waits for the save acknowledgement before switching modes, and edits made during a save are synced before the queued mode switch. The browser journey presses Save then Code immediately after visual edits and checks the Markdown file and reopened Studio; this runtime assertion remains blocked here (`src/visual-ui.ts`, `scripts/ui-smoke.mjs`).
- The Save/mode ordering decision is now shared with a tested pure queue. Unit cases cover Save followed by Code across busy states, coalesced Save requests with the latest mode, and clearing actions after a source conflict (`src/core/visual-actions.ts`, `src/test/unit/visual-actions.test.ts`). This tests the queue itself; it does not replace the blocked browser journey.
- Read-only Studio states now disable Save, formatting buttons and formatting selectors. Source conflicts also freeze the visual draft so further edits cannot appear to save while writes are blocked; Code, Split and Copy visual Markdown remain available. Disabled controls receive a visible style. The browser journey now checks the read-only state on a page containing raw HTML, but cannot execute here (`src/visual-ui.ts`, `src/visual.ts`, `scripts/ui-smoke.mjs`).
- The real code-server run reached `Home.md` in native Code mode but timed out on the smoke test's `.view-lines` DOM selector. Its failure screenshot shows the Text Editor and source Markdown. The browser regression now checks Monaco's visible editor input, which remains present across line-rendering modes, and confirms the code-server Text Editor label. The same renderer-independent check covers Code after Save and Split; no application behavior or assertion outcome was bypassed (`scripts/ui-smoke.mjs`, `docs/screenshots/failure.png`).
