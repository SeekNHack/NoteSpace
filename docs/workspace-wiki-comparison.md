# Workspace Wiki comparison (Phase 08)

[Workspace Wiki](https://github.com/AlexJSully/workspace-wiki) is a GPL-3.0 VS Code extension that lists documentation files of a workspace in a sidebar tree and opens them in the Markdown preview or editor. This comparison is based on its public README and settings reference (read on 2026-10-15). **No Workspace Wiki source code was read into or copied into NoteSpace**; every change below is an independent implementation of a general concept (for example, `.gitignore` matching is written from Git's documentation).

## Classification

| Area                                 | Workspace Wiki                                                               | NoteSpace before 1.10.0                                                                                      | Classification                           | Result in 1.10.0                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Front matter titles                  | `title` replaces the file name                                               | `title`, else the first `#` heading, else the file name; used everywhere (tree, links, search, export)       | Already implemented and correct (richer) | unchanged                                                                                                                                                                                                                                                                                                                                                                                    |
| Human-readable file names            | `user-guide.md` → “User Guide”, acronym list                                 | File name shown as is (`user-guide`)                                                                         | Implemented but inferior                 | **Readable labels** in the Pages view for folders and for pages whose title is their file name; `notespace.explorer.acronyms`; `humanizeNames` to turn it off. Titles used for `[[links]]` are unchanged                                                                                                                                                                                     |
| README / index handling              | README first; index represents its folder                                    | `index.md` used for the homepage, section order and the site; listed among pages by name                     | Implemented but incomplete               | `index.md` and `README.md` are listed first in their folder. A folder is not replaced by its index page: a clickable folder that also opens a page would make expanding it unreliable                                                                                                                                                                                                        |
| Directory sorting                    | `files-first`, `folders-first`, `alphabetical`                               | Folders always first; `navigation.sort` (filename, title, front matter `order`)                              | Implemented but inferior                 | `notespace.explorer.directorySort`: `folders-first` (default), `files-first`, `mixed`; `navigation.sort` still orders within groups                                                                                                                                                                                                                                                          |
| `.gitignore`, nested files, negation | Respected by default                                                         | Only `notespace.exclude` (one glob)                                                                          | Missing and worth adding                 | **`notespace.respectGitignore`**: every `.gitignore` of the workspace folder, nested files, `!` negation, anchoring, directory-only and `**` patterns; applied to full scans, file events and the 30-second reconciliation; editing a `.gitignore` re-applies it. **Off by default**, so notes that are deliberately ignored by Git (private drafts) do not disappear from an authoring tool |
| Include/exclude patterns             | `includeGlobs`, `excludeGlobs`, `maxSearchDepth`, hidden files               | `notespace.root`, `notespace.exclude`, `maxPages`, size limits                                               | Already implemented (different shape)    | unchanged; size and count limits are more useful for an index than a depth limit                                                                                                                                                                                                                                                                                                             |
| Custom document types                | `md`, `markdown`, `mdx`, `txt` plus any extension with a custom open command | Pages are `.md`; notebooks, canvases, dashboards and OpenAPI files have their own groups, editors and embeds | Not appropriate for NoteSpace            | A page must be editable in Studio with byte-identical round-trips, link rewriting and export; listing arbitrary file types as pages would break those guarantees. Other formats are integrated through dedicated features instead                                                                                                                                                            |
| Auto-reveal of the active document   | `autoReveal`, `autoRevealDelay`                                              | Always on                                                                                                    | Implemented but less configurable        | `notespace.explorer.autoReveal` (default on). No delay setting: the reveal does not move focus, so a delay adds nothing                                                                                                                                                                                                                                                                      |
| Open behavior per type               | Preview or editor on click; command per extension                            | Studio, or Code when Studio cannot round-trip the page                                                       | Implemented but less configurable        | **`notespace.openPagesIn`**: `studio` (default), `code` or `preview` for pages opened from the Pages view, search and links. Per-extension commands are not needed (see custom types)                                                                                                                                                                                                        |
| Multi-root                           | Per-folder `.gitignore` and depth                                            | Multiple wikis per workspace, per-folder settings, wiki.yaml projects                                        | Already implemented and correct          | `.gitignore` rules and the new settings are per workspace folder (resource scope)                                                                                                                                                                                                                                                                                                            |
| Web extension                        | — (not described)                                                            | Not a web extension: PDF export, Git, notebooks, code runner and the MCP server need Node.js                 | Not appropriate now                      | unchanged; documented                                                                                                                                                                                                                                                                                                                                                                        |
| Virtual workspaces                   | — (not described)                                                            | Declared supported; file access goes through `vscode.workspace.fs`                                           | Already implemented                      | the new `.gitignore` reading also uses `vscode.workspace.fs`                                                                                                                                                                                                                                                                                                                                 |
| Telemetry, local-only                | No telemetry                                                                 | No telemetry, local-first (SECURITY.md)                                                                      | Already implemented and correct          | unchanged                                                                                                                                                                                                                                                                                                                                                                                    |
| Tests and architecture               | —                                                                            | Pure core modules with unit tests, extension-host tests, code-server and desktop journeys                    | Already implemented (broader)            | new unit tests (`navigation.test.ts`), an extension-host discovery test and the `test:phase08` browser journey                                                                                                                                                                                                                                                                               |

## Not adopted

- A separate “documentation tree” of every text file in the workspace: NoteSpace's Pages view is a wiki, with links, backlinks and Studio editing tied to it.
- Replacing a folder with its index page in the tree (see above).
- Changing page titles themselves: readable labels are display-only, so existing `[[Title]]` links, search and exports behave as before.
